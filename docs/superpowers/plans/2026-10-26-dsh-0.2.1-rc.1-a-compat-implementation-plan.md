# DSH 0.2.1-rc.1 及以上版本适配 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 `dsh-plugin-archived-sessions` 能被 DSH `0.2.1-rc.1` 及同一 minor 的后续预发布版本正常准入、加载和运行，同时保持现有 `0.1.7-rc.1` / `0.2.0-rc.1` 声明范围不回归。

**Architecture:** 本插件运行时已按能力探测，不需要新增版本分支。实际阻断点是 bundle manifest 的 semver peer 范围 `^0.2.0-rc.1` 不包含 `0.2.1-rc.1`；同时本地 Typert generator 与 vendored protocol 仍停留在 0.1.7，无法生成 0.2.1 需要的 `./remote-info` strict codec 产物。计划只更新版本边界、协议 vendor/shim、构建依赖、生成产物和文档，不改 Host / Client 业务逻辑。

**Tech Stack:** TypeScript、React 18、DSH Typert Remote、Cordis、pnpm workspace、node:test、tsdown。

## Global Constraints

- 运行时能力检测只能使用 `typeof` 探测，不得新增版本字符串比较。
- 缺失能力必须继续返回 domain result，不允许启动硬失败。
- 不修改 `src/host/compat/restore.ts`、`src/host/session-log.ts`、`src/host/workspace-registration.ts` 的既有探测逻辑，除非验证证明 0.2.1 API 实际破裂。
- 不手改 `lib/typert.host.js` / `lib/typert.remote-client.js`；它们必须由 Typert generator 生成。
- 不顺手升级 `@deepseek-ai/cordis`、cosmokit、schemastery 或无关依赖。
- `@deepseek-ai/cordis` 的 peer 保持 `^4.0.1`；已确认该范围匹配 0.2.1 所需的 `4.0.5`。
- 新增 peer 范围必须是 `^0.1.7-rc.1 || ^0.2.0-rc.1 || ^0.2.1-rc.1`，不得只写 `^0.2.1-rc.1` 而丢掉旧版本。
- 使用与 DSH app-boot 相同的 semver 语义：`semver.satisfies(runtimeVersion, range, { includePrerelease: true })`。
- 0.2.1 真实校验环境为 `D:/code/ai/dsh-g0-bench/dsh021`（`0.2.1-rc.2`、`cordis@4.0.5`）；`0.2.1-rc.1` 本身由静态 semver 断言覆盖。

# Implementation Plan

## 1. Goal

### 本次修改目标

1. 放宽插件 package manifest 中的 DSH peer 范围，使 `0.2.1-rc.1` 以及 `^0.2.1-rc.1` 覆盖的后续补丁预发布版本通过 DSH bundle 准入。

3. 重新生成并提交 `lib/` 产物与 lockfile，保证发布包不是 0.1.7 构建的产物。
4. 更新 README 的支持范围说明，明确已验证 `DSH 0.2.1-rc.1` 及以上。
5. 用静态 semver 检查和 `0.2.1-rc.2` 实机环境验证准入与启动。

- 不新增归档会话功能，不改 list / details / restore / delete / workspace 行为。
- 不重构 Host Remote、Client store、UI 组件或兼容 adapter。
- 不为未来 DSH 版本提前抽象版本适配层。
- 不新增运行时版本探测，不读取 `getDshRuntimeVersion()` 做功能分支。
- 不修复与本次版本适配无关的既有问题（例如 `zod` 是否应进入运行时 `dependencies`、details 冷读性能）。
- 不升级 vendored `cordis`（保持 4.0.1）或 cosmokit / schemastery，除非构建出现与 0.2.1 类型面直接相关的阻塞并在 Plan Adjustment 中说明。
- 不修改 `docs/dsh-0.1.7-rc.1-impact.md` 的历史记录；只在本计划执行日志中记录本轮结论。

## 2. Current Understanding

### 2.1 当前实现方式

插件通过 Typert Remote 暴露 Host 能力，Client 通过 `ctx.remote.$mount` 消费自身 Remote：

- Host:
  - `packages/dsh-plugin-archived-sessions/src/index.ts`
  - `ArchivedSessionsService extends TypertRemoteService`
  - 6 个 endpoint：`list`、`details`、`restore`、`delete`、`deleteWorkspace`、`deleteWorkspaceRegistration`
- Host 兼容模块:
  - `src/host/compat/restore.ts`
  - `src/host/session-log.ts`
  - `src/host/workspace-registration.ts`
- Client:
  - `src/client/index.ts`
  - `src/client/store.ts`
  - `src/client/ArchivedSessionsSection.tsx`
- 构建:
  - `tsdown.config.ts` 使用 `@deepseek-ai/dsh-typert-generator/tsdown`
  - 根 `package.json` 固定 generator `0.1.7-rc.1`
  - `packages/dsh-typert-protocol` 是 vendored 的 `0.1.7-rc.1` 公开构建
- bundle 声明:
  - 插件 `dsh.bundle.patch` → `cordis.patch.yml`
  - 根 `dsh.bundle.patch` → 根 `cordis.patch.yml`

### 2.2 数据流 / 调用链

```
Settings UI
  → ArchivedSessionsSection
  → ArchivedSessionsStore
  → ctx.remote.archivedSessions.*
  → ArchivedSessionsService
      ├─ ctx.workspaceRegistry.archivedSessionIds / list() / unarchiveSession()
      ├─ ctx.sessionPersistence.list() / open(id,'read') / listArtifacts() / locate()
      ├─ ctx.sessions.get() / snapshotEvents()
      └─ ctx.agents.get()
```

0.2.1 仍保留上述 API：

- `WorkspaceRegistry.archivedSessionIds`
- `WorkspaceRegistry.list()`
- `WorkspaceRegistry.unarchiveSession()`
- `WorkspaceRegistry.delete(id)`
- `SessionPersistence.list()` / `open(id,'read')`
- `SessionStore.get()` / `Session.snapshotEvents()`
- `AgentRegistry`

`SessionPersistence.root`、`listArtifacts`、`locate` 不在 0.2.1 公开抽象基类中，仍是 JSONL backend 运行时扩展面；现有 optional + `typeof` 探测必须保留。

### 2.3 已确认的真实阻断点

`@deepseek-ai/dsh-app-boot@0.2.1-rc.1` 的 `evaluatePluginCompatibility()`：

```js
function satisfies(runtimeVersion, range) {
  return range.trim() !== "" && semver.satisfies(runtimeVersion, range, { includePrerelease: true });
}
```

逐个检查 `@deepseek-ai/dsh` 或 `@deepseek-ai/dsh-*` peer：

```js
if (name !== "@deepseek-ai/dsh" && !name.startsWith("@deepseek-ai/dsh-")) continue;
if (!satisfies(runtimeVersion, range)) unmet[name] = range;
```

当前插件 peer 为 `^0.2.0-rc.1`，该范围不匹配 `0.2.1-rc.1`。验证结果：

```
^0.1.7-rc.1 => 0.1.7-rc.1, 0.1.7-rc.2
^0.2.0-rc.1 => 0.2.0-rc.1, 0.2.0-rc.2, 0.2.1
^0.2.1-rc.1 => 0.2.1-rc.1, 0.2.1-rc.2, 0.2.1-rc.3, 0.2.1
```

注意 `^0.2.0-rc.1` 名义上接受 stable `0.2.1`，但不接受任何 `0.2.1-*` 预发布版本。本需求的目标版本 `0.2.1-rc.1` 正好落在缺口内。

### 2.4 已确认的构建链阻断点

0.2.1 generator 生成的 host artifact 包含：

```js
import { createTypertRemoteInfo } from '@deepseek-ai/dsh-typert-protocol/remote-info'
```

当前 vendored protocol `0.1.7-rc.1`：

- `package.json` 没有 `./remote-info` export
- `lib/` 没有 `remote-info.js` / `remote-info.d.ts`
- `src/` 只有 `index.ts` / `types.ts` 两个 source-plane shim
- `scripts/sync-shims.mjs` 只生成这两个 shim

0.2.1 发布版 protocol 新增：

- `lib/types/remote-info.js` / `.d.ts`
- `package.json` export `"./remote-info"`
- 新的 value exports：`createTypertRemoteInfo`、`isTypertRemoteMethod`、`principalOf`
- 新的 type exports：`TypertRemoteInfo`、`TypertRemoteValue`、`TypertRemoteCodecSpec`、`TypertRemoteParameterSpec`、`TypertRemoteMethodSpec`、`TypertRemoteSpec`、`TypertResource*`、`Principal*`、`RemoteDecoded`、`RemoteWire*` 等

因此仅改写插件 peer 范围不足以完成适配。必须同步 vendor protocol 的 `lib/`、`exports` 与 source-plane shim。

### A2: client bundle 需外置 `remote-info`（2026-10-26，已确认）

**Original plan**

Step 5 只重新构建插件产物，并检查 `create:` / strict codec；没有调整 client external 列表。

**New finding**

0.2.1 generator 生成的 `lib/typert.remote-client.js` 新增：

```js
import { createTypertRemoteInfo } from '@deepseek-ai/dsh-typert-protocol/remote-info'
```

现有 `tsdown.config.ts` 的 `noExternal` 把所有 `@deepseek-ai/*` 视为 external，导致该模块未被外置，构建把 `remote-info` 及其 `zod` 依赖一起内联进 `lib/client.js`：

**Revised scope**

- 修改 `packages/dsh-plugin-archived-sessions/tsdown.config.ts`：在 `PLATFORM_MODULES` / `CLIENT_EXTERNALS` 增加 `@deepseek-ai/dsh-typert-protocol/remote-info`
