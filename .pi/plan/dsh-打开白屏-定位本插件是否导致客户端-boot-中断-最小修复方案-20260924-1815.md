## 能造成“整页白屏”的机制（在随包运行时里已确认，共 3 条）

1. `@deepseek-ai/dsh-typert-loader/lib/index.js:77 validateTypertManifest` / `:206 requireStrictCodec` 拒绝某包 `./typert` → 同 fiber 的全部 strict 定义回滚（`docs/dsh-0.1.7-rc.1-impact.md` 记录的既有事故）。
2. `@deepseek-ai/dsh-client-modules/lib/index.js` 激活扫描（`ClientPackageCompositionError`、`resolveMeta`、`captureArtifactBaseline`）抛错 → 不再向 index.html 注入 boot 行 → 前端 `web boot: window.__ModuleLoader__ bootstrap facade is missing`。
3. **客户端 boot 审计是全有全无**：`@deepseek-ai/dsh-web-frontend/dist/assets/index-3dwByubT.js` 的 `run()` → `tE()`（`loader.entries.start` → `await loader.await()` → `nE()`）→ 任一入口非 active 即 `throw new Error('web boot: N entries did not activate\n<id>: pending (waiting for service: X) | import failed | failed')` → `run()` catch → 只渲染 boot 卡片，**整个应用不挂载**（用户看到的“白屏”）。第三方 `@dsh-external/dsh-super-injector` 也在同一 profile 内（其 `self-heal.log`/`reload-debug.log` 记录对 `client-modules` pkgMeta 的清理与 reload）。

## 风险 / 注意点

- **需求前提尚未被证据证实**：现有证据（host 契约 PASS、客户端 bundle 可物化、0.1.7 客户端 API 齐全、产物与源码同步）都不支持“本插件代码导致白屏”。能造成整页白屏的第 3 条机制是**全有全无**的，污点可能是本插件，也可能是同一 boot 的其它 client 条目或 profile 装配。必须先用第 1 步拿到审计原文再定位，否则任何改动都是猜测。
- `docs/dsh-0.1.7-rc.1-impact.md` 自述“真实 UI 冒烟未做”，本轮新增的 `details` 恰好落在这一未验证区：客户端新增了 `mounted.archivedSessions.details(...)` 调用与 `loadDetails` 水合（`store.ts:143`、组件 `:223-236`），从未在真实 UI 里跑过。
- **`zod` 未声明为运行时依赖**（`package.json:100` 仅 devDependencies；`files` 清单包含 import zod 的两个产物）：在本机靠 pnpm workspace link 侥幸可解析；任何裁掉 devDeps 的安装（`pnpm i --prod`、npm 发布/安装）都会让 `./typert` import 失败 → 触发第 1 条机制（整 fiber strict 回滚）。这是本仓真实缺陷，但**尚不能证明是本次白屏原因**。
- 客户端产物 rev 由 `mtime/ctime/size` 决定（`artifactRevision`）且以 `immutable` 缓存；17:15 的重建已引发一次 HMR reload，调试时需以“全新启动 + 全新页面”为基准，避免把 HMR 残留当根因。
- 修复时不得用“在 profile 里禁用/加墓碑”当解决方案（墓碑上周刚清理），也不得改 profile 或其它 5 个本地插件来掩盖问题。
